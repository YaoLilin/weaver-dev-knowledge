
## 动作流推送

使用动作流实现统一待办推送

参考文档：[https://www.e-cology.com.cn/sp/doc/docDetail/2004679863277257087](https://www.e-cology.com.cn/sp/doc/docDetail/2004679863277257087)

### 动作流传入参数说明

- iutIsRemark：流程审批状态，值说明：
	- 删除： -1 
	- 待办：0
	- 已办：2
	- 办结：4
- operateType：流转操作类型，类型如下
	- SUBMIT_END：流程提交
	- REJECT_END：退回
	- TURN_TO_DO_END：转办
	- FORCED_RAWBACK_END：强制收回

- realUserId：真实身份id，也就是流程操作人id

	注意：流程地址传过去是不带域名的，需要手动拼接域名

### 动作流返回参数（一定要配置）

此参数一定要配置，不然统一待办会因没有返回参数而视为推送异常。

在接口执行成功时，终止的参数返回状态为200，接口执行失败时，参数返回状态为500，其它情况（例如没有执行接口）参数中的状态返回200。

code 是一定要配置的，其它可以选配，code 为200表示推送成功，message 配置为接口的返回信息即可。

code 可以配置为 500 ，或使用接口返回的状态码（需要为数字，与 http 状态码一致），message 为接口返回的错误信息

### 注意事项

在生产环境中请勿对推送的同一个系统使用多个推送方案，避免造成数据异常，如果使用多个需要确保金智的任务id一致，以及判断是否新增金智任务的逻辑一致。在一开始就应该只使用一个推送方案。比如说一开始用的是一个推送方案，后来发现这个方案不行，就改成了另一种，可能会造成以前推送过去的待办数据，在使用另一种方案后无法更新以前的待办数据了。
