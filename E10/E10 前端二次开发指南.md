## ecode 开发

### E-Code 平台介绍

E-code 平台的功能和 E9 的 E-Code 平台差不多，它是一个在线的前端代码编辑器，可编写 React 组件以及注册事件，可实现修改标准页面的组件和数据，以及创建自定义页面、进行接口拦截等。

E-Code 页面进入链接： `/ecode`

进入页面后是一个项目列表，你可以在这里创建项目

![](files/Pasted%20image%2020260614143623.png)

进入项目后就可以在此页面创建 E-Code 应用，发布该应用后就可以让该应用生效。

**应用ID**：
右键点击 E-Code 应用，选择 `属性` 可查看应用信息，其中应用ID分为 `appId` 和 `appUUID` , 需要注意 `appId` 是可变的，导入到其它 E10 系统后 ID 可能会变，而 `appUUID` 是不变的，所以在代码中需要使用应用 ID 时，尽量使用 `appUUID`。

### 接口拦截

#### 使用 axios 进行拦截

有标准的拦截接口，如无必要不要使用 axios 拦截

##### 请求拦截

```javascript
// 前置拦截，获取请求数据
axios.interceptors.request.use(
  config =>{
    // config 包含所有请求信息
    const {url,params} = config;
    if(url.includes('api/hrm/employee/getTopMenu')){
      // 添加参数
      params.isTest = 1;
    }
    return config;
  },
  error =>{
    // 对请求错误做些什么
    return Promise.reject(error);
  }
)
```

##### 响应拦截

```javascript
// 后置拦截，获取接口返回数据
axios.interceptors.response.use(
  response =>{
    // response 里包含了响应信息，以及 config，使用 config 可以获取请求信息，data可以获取响应数据
    const {data,config:{url,params}} = response;
    if(url.includes('api/hrm/employee/getTopMenu')){
      // 能够获取到上面请求拦截中添加的参数
     const {isTest} = params;
      // 修改返回数据，添加一个按钮
      if(data.data){
        data.data.push({
          content:'新增按钮',
          id:'devBt'
        });
      }
    }
    return response;
  },
  error =>{
    // 对请求错误做些什么
    return Promise.reject(error);
  }
)
```

// 页面id
const pageId = '1002553806419304452';
    
function renderCom(dom){
  ReactDOM.render(CustomConent ,dom);
}
    
regOvProps('weappEBpage','PageView',(props)=>{
  if(props.pageId === pageId){
    let time=0;
    const interval = setInterval(()=>{
      // 找到对应的ebuilder组件，comId为组件id
      const dom = document.querySelector(`#${comId}`);
      if('ebuilderSDK' in window && dom){
        clearInterval(interval);
        renderCom(dom);
      }
      if(time++ > 50){
        clearInterval(interval);
        console.warn('未找到对应的e-builder组件')
      }
    },100)
  }
})

### 流程 SDK
#### 流程表单添加菜单按钮

不要在 e-code 入口执行时立即调用 `getFlowPageSDK()` 并添加菜单：此时流程 SDK 可能尚未初始化，导致按钮未注册。应注册 PC 流程表单挂载钩子 `FPMainTabWillMount`，再在 `onceReady` 回调中添加菜单。

`regHook` 的作用是向 E10 已提供的模块生命周期事件注册回调。它不是“等待 SDK 已就绪”的方法：在本场景中，`regHook('weappWorkflow', 'FPMainTabWillMount', registerFlowMenu)` 让 `registerFlowMenu` 在 PC 流程表单主页签开始挂载时执行；回调中再调用 `flowSdk.onceReady(...)`，才能保证当前流程 SDK 已完成初始化后再注册菜单。

两者分工如下：

- `regHook`：选择正确的页面生命周期和作用范围，解决入口脚本执行过早、以及流程表单重新载入时需要再次执行的问题。
- `onceReady`：等待本次流程表单的 SDK 可用，之后才能安全调用 `addOperMenu`、`registerInterceptEvent` 等流程 SDK 方法。

entry.js :

```javascript
import { regHook } from '@weapp/utils';

const registeredSdkSet = new WeakSet();
const menuType = 'custombtn_flow_form_test';

function registerFlowMenu() {
  const flowSdk = window.weappWorkflow?.getFlowPageSDK?.();

  if (!flowSdk) {
    console.error('流程表单菜单：流程 SDK 未创建');
    return;
  }

  // 单页路由或重复挂载时，避免对同一个 SDK 重复添加菜单。
  if (registeredSdkSet.has(flowSdk)) {
    return;
  }
  registeredSdkSet.add(flowSdk);

  flowSdk.onceReady(() => {
    flowSdk.addOperMenu({
      id: 'flow_form_test_button', // 应用内唯一
      menutype: menuType, // 自定义且唯一，用于绑定点击拦截
      title: '测试按钮',
      istop: true, // 显示在顶部操作区
    }, 'Last');

    console.log('流程表单菜单：按钮已注册');

    flowSdk.registerInterceptEvent(
      `BeforeClickOperBtn|${menuType}`,
      (successFn, failFn, params) => {
        console.log('流程表单菜单：按钮已点击', params);
        successFn();
      },
    );
  });
}

regHook('weappWorkflow', 'FPMainTabWillMount', registerFlowMenu);
```

验证方法：在流程表单地址后增加 `wea_link_keep_show_console`，刷新页面。控制台出现“按钮已注册”且顶部显示按钮，说明注册成功；点击后应出现“按钮已点击”。若入口日志存在、但没有“按钮已注册”，优先检查流程 SDK 就绪时机。

```javascript
function onDetailReady(detailKey, callback) {
  const maxTime = 10000;
  const timeout = 100;
  let count = 0;
  const formSdk = window.WeFormSDK.getWeFormInstance();
    
  const interval = setInterval(() => {
    count++;
    const detailMark = formSdk.convertFieldNameToId(detailKey);
    const rowIdStr = formSdk.getDetailAllRowIndexStr(detailMark);
    if (rowIdStr) {
      callback(rowIdStr);
      clearInterval(interval);
    }
    if (count * timeout > maxTime) {
      console.warn('等待明细加载超时');
      clearInterval(interval);
    }
    
  }, timeout);
    
}
    
```

### FormSwitch - 表单组件分发

下面这个是我做的流程表单助手功能，它能查看表单中的所有字段，显示的组件与表单中的字段组件一致，就是通过复制字段组件实现

组件说明：[e-cology.com.cn/sp/form/components/FormSwitch?ticket=ST-7374-UZ1hsJZqHEs3adc7Vmz1-https://www.e-cology.com.cn](https://www.e-cology.com.cn/sp/form/components/FormSwitch)

案例：[Ecode-表单明细树组件](Ecode-表单明细树组件.md)

**简单示例**   
`config`  是重点，它决定能不能复制字段组件，它包含了表单字段组件的参数，可以从表单 SDK 获取字段组件参数，传入 `config` 中。`value` 是字段组件的值，与表单 SDK 获取的字段值不一样，需要进行转换。

```javascript
<CorsComponent  
    app="@weapp/formbuilder"  
    compName="FormSwitch"  
    config={componentDefinition.config}  
    isNewDataFormat  
    onBlur={() => {}}  
    onChange={() => {}}  
    rowId={componentData.rowId}  
    value={componentValue}  
/>
```

#### 使用 SDK 属性复制字段组件

从表单 SDK 获取原字段的配置和字段值，再通过 `CorsComponent` 加载表单引擎的 `FormSwitch`。`FormSwitch` 根据 `config.componentKey` 分发到原字段对应的控件，无需分别创建文本、选择、人员或附件组件，也无需复制或修改原字段的 HTML。

配置使用 `formSdk.getFieldInfo(fieldId)` 获取，保留完整返回对象，不要只提取标题和组件类型。值使用 `formSdk.getFieldObj(fieldMark)` 获取，再将 SDK 的 `value`、`specialObj` 转为组件需要的 `content`、`dataOptions`。明细字段使用同一列配置，但必须按当前行的 `rowId` 获取值和读写属性。

#### CorsComponent 参数说明

| 参数 | 本场景的取值 | 说明 |
| --- | --- | --- |
| `app` | `"@weapp/formbuilder"` | 被加载组件所属的应用包。 |
| `compName` | `"FormSwitch"` | 加载表单字段组件分发器，由 `config` 决定具体字段控件。 |
| `config` | SDK 字段配置对象 | 来自 `getFieldInfo(fieldId)`，包含 `fieldId`、`componentKey`、标题、选项及控件配置等；可在副本中调整 `readOnly`、`disabled`，不要修改 SDK 原对象。 |
| `isNewDataFormat` | `true` | 使用本示例的字段数据对象格式，即 `content`、`dataOptions` 等，而不是直接传字符串。 |
| `value` | 字段数据对象 | 原字段当前值。文本内容放入 `content`；选项和浏览数据放入 `dataOptions`，每项包含 `optionId`、`content`，有扩展信息时保留 `optionObj`。 |
| `onChange` | `(newValue) => …` | 复制控件值改变时触发，收到的是新字段数据对象，不是 DOM 事件；更新本地 `value`，并将新值转换为 SDK 格式回写原字段。 |
| `onBlur` | `() => …` | 可选。可将 `onChange` 收到的值暂存，失焦后再提交，避免输入过程中频繁触发表单联动。 |

`config` 决定字段的显示方式，`value` 决定显示内容，两者必须来自同一字段（明细还必须是同一行）。仅传字段 ID 或数据库值，不能完整复制浏览名称、选项或附件信息。附件、自定义浏览等字段需要保留 SDK `specialObj[].data`，转换为组件的 `dataOptions[].optionObj`，不能只保留 ID 和名称。

`getFieldInfo()` 中的 `readOnly` 不应作为当前节点读写权限的唯一依据。使用 `getFieldAttr(fieldMark)` 获取当前字段或明细行字段的属性：`1` 为只读、`2` 为可编辑、`3` 为必填、`4` 为隐藏、`5` 为隐藏行；同时结合 `getBaseInfo().isEditable`。如果只用于展示，可在配置副本中统一设置 `readOnly: true`、`disabled: true`。

#### 复制字段，并在 onChange 中回写原表单

下面示例传入已就绪的 `formSdk` 和 SDK 获取的 `fieldId`。主表不传 `rowId`；明细传入对应行的 `rowId`。字段 ID 按字符串使用，避免大整数精度丢失。

```javascript
import React, { useState } from 'react';
import { CorsComponent } from '@weapp/ui';

/**
 * 将 SDK 字段值转换为 FormSwitch 的字段数据对象。
 * @param {Object} fieldValue SDK getFieldObj 返回值
 */
function toComponentValue(fieldValue) {
    const value = { ...fieldValue, content: fieldValue.value };
    const hasSpecialOptions = Array.isArray(fieldValue.specialObj);
    if (hasSpecialOptions) {
        value.dataOptions = fieldValue.specialObj.map(option => ({
            optionId: option.id,
            content: option.name,
            optionObj: option.data,
            type: option.type,
        }));
    }
    return value;
}

/**
 * 将复制控件的新值转换为 SDK changeFieldValue 的入参。
 * @param {Object} newValue FormSwitch onChange 返回值
 */
function toSdkValue(newValue) {
    const value = { value: newValue.content };
    const hasDataOptions = Array.isArray(newValue.dataOptions);
    if (hasDataOptions) {
        value.specialObj = newValue.dataOptions.map(option => ({
            id: option.optionId,
            name: option.content,
            data: option.optionObj,
            type: option.type,
        }));
    }
    return value;
}

/**
 * 复制主表字段或指定明细行字段，值变更后同步原表单。
 * @param {Object} formSdk 已就绪的表单 SDK 实例
 * @param {string} fieldId SDK 获取的原字段 ID
 * @param {string} [rowId] 明细行 ID，主表不传
 * @param {string} appId 当前 ecode 应用 ID，仅用于二开样式标记
 */
function CopiedFormField({ formSdk, fieldId, rowId, appId }) {
    const isDetailField = rowId !== undefined && rowId !== null;
    const fieldMark = isDetailField ? `${fieldId}_${rowId}` : fieldId;
    const fieldInfo = formSdk.getFieldInfo(fieldId);
    const fieldAttr = formSdk.getFieldAttr(fieldMark);
    const isReadOnly = fieldAttr === 1 || !formSdk.getBaseInfo().isEditable;
    const fieldConfig = {
        ...fieldInfo,
        readOnly: isReadOnly,
        disabled: isReadOnly,
    };
    const [value, setValue] = useState(() => (
        toComponentValue(formSdk.getFieldObj(fieldMark))
    ));

    const handleChange = (newValue) => {
        // 复制控件是受控组件，先更新其显示值。
        setValue(newValue);
        // 再同步原字段；空 dataOptions 转为空 specialObj，可清空浏览值。
        formSdk.changeFieldValue(fieldMark, toSdkValue(newValue));
    };

    return (
        <div className={`appid-${appId} seconddev-ecode`}>
            <CorsComponent
                app="@weapp/formbuilder"
                compName="FormSwitch"
                config={fieldConfig}
                isNewDataFormat
                value={value}
                onChange={handleChange}
            />
        </div>
    );
}
```

示例演示初始化与复制控件向原表单回写；原表单因联动等原因从外部改变时，还需在对应 SDK 值变更回调中刷新本地 `value`。隐藏字段或隐藏行应按业务要求处理，不应当作可编辑字段直接展示。

#### 输入缓冲与失焦回写

需要避免逐次输入触发表单联动时，可以在复制控件中管理缓冲状态：`onChange` 接收 `newValue`，更新本地 `value` 并标记值已变更；使用 `useRef` 保存最新缓冲值，供稳定的失焦回调读取。`onBlur` 仅在值发生变更时提交，将缓冲值转换为 SDK 格式后调用 `formSdk.changeFieldValue`，并清除变更标记。若复制控件所在的表格还管理了独立数据，也应在提交后同步更新对应行和字段的数据。

`CorsComponent` 并不会自动修改原字段：需要自行提供回调。需要即时回写时使用上面的 `handleChange`；需要缓冲输入时，则在 `onChange` 中只暂存，把 `changeFieldValue` 移到 `onBlur` 中执行。原字段从外部改变时，只有在未缓冲输入的情况下才用外部值刷新本地状态，避免覆盖用户正在输入的内容。明细字段标识中的行 ID 只拼接一次，例如 `${fieldId}_${rowId}`，不能重复追加 `_${rowId}`。

#### SDK 无字段配置时：通过后端复制布局外字段

字段已经创建但未放入当前表单布局时，`formSdk.getFieldInfo(fieldId)` 可能取不到配置。此时不能仅凭字段类型自行拼一个控件配置，也不能用另一个字段的配置代替；应由后端分别查询字段元数据和完整表单数据，按字段 ID 合并，再把配置和值交给同一个 `CorsComponent/FormSwitch`。

##### 后端调用的 RPC 接口

以下接口用于流程表单，字段信息与字段值需要分别获取：

| 用途      | RPC 接口与方法                                                     | 返回对象及作用                                                               |
| ------- | ------------------------------------------------------------- | --------------------------------------------------------------------- |
| 全部字段清单  | `FormFieldRest.listAllFormFieldByFormId(formId, 0, employee)` | `List<SimpleFormFieldDto>`，枚举未删除的主表字段及明细字段，不依赖当前布局。简化 DTO 不能代替完整组件配置。 |
| 完整字段元数据 | `FormFieldRest.getFieldMapByFormId(formId, employee)`         | `Map<Long, FormField>`，key 为字段 ID，value 为字段元数据；用来提取数据库列名和组件配置。        |
| 完整字段值   | `WfcFormDataRest.getFullFormData(dataId, employee)`           | `FormData`，从 `getDataDetails()` 获取字段数据记录，包含布局外字段的数据。                  |

`FormFieldRest` 的完整类名为 `com.weaver.common.form.api.rest.field.FormFieldRest`，可通过注入的 `FormRestFactory` 按流程分组取得；`WfcFormDataRest` 的完整类名为 `com.weaver.workflow.core.api.rest.publicapi.WfcFormDataRest`。

后端调用示意（`formRestFactory` 和 `wfcFormDataRest` 均由平台注入）：

```java
// 使用当前登录用户作为权限上下文，不使用管理员账号兜底。
SimpleEmployee employee = UserContext.getCurrentUser();
FormFieldRest formFieldRest = formRestFactory.getFormFieldRest(
        RpcGroup.WORKFLOW.getValue());

List<SimpleFormFieldDto> fields = formFieldRest.listAllFormFieldByFormId(
        formId, 0, employee);
// key：字段 ID；value：完整字段元数据。
Map<Long, FormField> metadata = formFieldRest.getFieldMapByFormId(
        formId, employee);
FormData formData = wfcFormDataRest.getFullFormData(dataId, employee);
List<FormDataDetail> values = formData.getDataDetails();
```

RPC 的 `group` 应匹配目标接口的实际发布配置，不能将所有接口都写成 `group = "workflow"`。在已核实的调用中，`WfcFormDataRest` 使用不带 `group` 的 `@RpcReference`；错误分组会导致 `instance does not exist`。

##### 从哪些对象提取配置和值

组件配置从 `FormField` 获取：先解析 `getLayoutDetail()` 返回的 JSON，提取其中的 `config` 对象；没有有效 `config` 时，再解析 `getOtherProperties()` 返回的字段扩展配置。布局外字段尤其需要检查后者。接口将解析后的 JSON 对象作为 `componentConfig` 返回，并同时返回字段的 `fieldId`、`componentKey`。这两处均没有有效配置时，应明确返回配置缺失，不能保证仅靠字段类型就能复制组件。

字段值从 `FormDataDetail` 获取：普通内容读取 `getContent()`；选项、浏览和附件读取 `getDataOptions()`，每项为 `FormDataOption`，包含 `optionId`、`content`、`type`、`optionObj`。按字段 ID 将值与元数据对应起来；明细字段还需按所属明细表和行身份归组，不能把不同明细行的值合并到一起。

`FormData.getDataDetails()` 的名称不代表它只包含明细表。主表字段也以 `FormDataDetail` 记录返回；主表、明细归属应依据字段元数据及行信息判断。

后端应投影成自己的 DTO，不直接序列化 `FormData`、`FormDataDetail` 或完整平台附件对象，避免循环引用和不必要的内部数据暴露。例如字段 DTO 使用如下结构：

```javascript
{
    fieldId: '原字段ID',
    componentKey: '原字段组件类型',
    componentConfig: { /* FormField 中提取的完整有效配置 */ },
    value: {
        content: '原始字段内容',
        dataOptions: [
            {
                optionId: '选项或文件ID',
                content: '选项或文件名称',
                type: 'file',
                optionObj: { /* 附件等字段所需的扩展属性 */ },
            },
        ],
    },
}
```

##### 前端把后端数据放入 CorsComponent

后端已将字段值转换成 `content`、`dataOptions` 格式时，前端不需要再转为 SDK 的 `specialObj`；直接保留 `dataOptions` 及每项的 `optionObj`。下面以布局外主表字段的只读复制为例：

```javascript
/**
 * 使用后端字段 DTO 复制布局外主表字段的只读组件。
 * @param {Object} field 后端返回的字段，包含配置与字段值
 * @param {string} appId 当前 ecode 应用 ID，仅用于样式标记
 */
function BackendCopiedField({ field, appId }) {
    const hasComponentConfig = Boolean(field.componentConfig);
    const hasComponentKey = Boolean(field.componentKey);
    const canCopyComponent = hasComponentConfig && hasComponentKey;
    if (!canCopyComponent) {
        return <span>未获取到字段组件配置</span>;
    }

    const config = {
        ...field.componentConfig,
        fieldId: field.fieldId,
        componentKey: field.componentKey,
        readOnly: true,
        disabled: true,
        display: true,
        show: true,
    };
    const backendValue = field.value || {};
    const dataOptions = backendValue.dataOptions || [];
    const hasContent = backendValue.content !== null
        && backendValue.content !== undefined;
    const content = hasContent
        ? backendValue.content
        : dataOptions.map(option => option.optionId).join(',');
    const value = { ...backendValue, content, dataOptions };

    return (
        <div className={`appid-${appId} seconddev-ecode`}>
            <CorsComponent
                app="@weapp/formbuilder"
                compName="FormSwitch"
                config={config}
                isNewDataFormat
                value={value}
            />
        </div>
    );
}
```

调用端仍优先使用 SDK：SDK 有配置时采用前面的 SDK 复制方式；没有配置时，从后端返回的字段集合按 `fieldId` 找到目标字段，传入上述组件。这里的 `display`、`show` 只让配置在复制位置显示，不会把该字段添加到原表单布局。原表单数据的读权限仍由后端执行。

在流程表单助手中，已有后端接口为 `GET /api/secondev/hnweaver/form-assist/field-value?formId=表单ID&dataId=表单数据ID`，返回 `WeaResult`，字段位于 `data.mainFields` 或 `data.detailTables` 中。该接口当前仅允许登录的系统管理员调用；不要用前端展示条件替代后端权限校验。

##### 附件字段：配置完整还不够，文件元数据也必须完整

附件字段的组件配置与每个附件的文件属性是两类数据。以布局外“拼接文件”为例，即使拿到了与普通附件相同的组件配置，只返回文件 ID 和名称也只能显示文件名，不能完整恢复预览、下载和上传信息。

附件元数据读取路径为：`FormDataDetail.getDataOptions()` → `FormDataOption.getOptionObj()`。本例已核实实际对象为 `com.weaver.eteams.file.client.file.FileObj`，而不是字段配置 `FormField`。后端需要从这个对象提取如下属性，放入响应的 `value.dataOptions[].optionObj`：

| 属性 | 来源和转换 | 组件用途或注意事项 |
| --- | --- | --- |
| `fileid`、`id`、`refId`、`docId` | `FileObj` 对应 getter，ID 转字符串 | 标识文件、引用和关联文档，避免前端大整数精度丢失；外层 `optionId` 也需保留。 |
| `name`、`type`、`size`、`extName` | `FileObj` 对应 getter | 文件名、MIME 类型、大小和扩展名，影响文件显示及识别。 |
| `doc`、`img`、`image`、`docType`、`fileStatus` | `FileObj` 对应 getter | 文档或图片类型、文件状态；不要根据文件名自行猜测。 |
| `uploadTime` | `getUploadTime()` 返回 `Date`，使用 `.getTime()` 转为毫秒时间戳 | 组件按上传时间渲染日期。非空 `optionObj` 缺少此属性时，组件执行 `new Date(undefined).getTime()` 会得到 `NaN`；不能只处理字符串和数字而丢弃 `Date`。 |
| `uploadUser`、`uploadEmployeeId`、`uploadUserName` | `FileObj` 提供上传员工标识；必要时查询同租户员工显示姓名 | 用于显示上传人。当前依赖中的 `getUploadUserName()` 实际返回 `uploadName`，不能仅依据 `toString()` 判断 getter 的值。已知上传员工 ID 时，可调用 `UserService.getSimpleEmployeeById` 获取同租户员工姓名；员工不存在或租户不匹配时不伪造姓名。 |
| `options` | `getOptions()` 返回 `List<FileOption>`；转换为普通 JSON 数组 | 组件检查是否存在 `id: "preview"` 才允许预览，并依据操作列表显示下载按钮。每项保留 `id`、`icon`、`content`、`moreType`；只读复制只保留平台实际返回的 `preview`、`download`，不自行授予操作权限。 |
| `loadlink`、`url`、`encryptId` | `FileObj` 对应 getter | 保留平台返回的文件链接和标识，不自行拼接下载 URL。缺少 `loadlink` 是数据不完整，但“提示不支持预览”的直接原因可能是缺少 `preview` 操作，应区分。 |
| `module`、`ban`、`signTip` | `getModule()` 转为模块名称，另取 `isBan()`、`getSignTip()` | 保留文件所属模块、禁止访问状态和签署提示，不能通过补操作绕过禁止状态。 |

`FileOption` 的完整类名为 `com.weaver.eteams.file.client.constant.FileOption`。`options` 是嵌套列表，不能交给仅支持标量属性的转换方法，否则即使加到属性白名单也会被丢弃。应逐项投影所需字段，排除重命名、替换、删除等修改操作，以及操作对象的 `url`、`cusMap` 等不必要的扩展信息。

前端必须把这些属性留在 `value.dataOptions[].optionObj`，不能移到 `config`，也不能把 `value` 简化成文件名或文件 ID 字符串。仍由 `CorsComponent/FormSwitch` 渲染附件组件，不需要单独创建附件展示组件。

#### 使用方法
以下是如何复制一个表单字段的用法：
需要使用 `CorsComponent` 组件，在 `compName` 参数中指定 `FormSwitch` , 示例：

```javascript
 <CorsComponent
      app="@weapp/formbuilder"
      compName="FormSwitch"
      config={fieldConfig}
      isNewDataFormat
      value={valueToRender}
      onChange={handleChange}
    />
```

**config 参数** ：
`config` 参数是字段的属性，决定这个字段是什么样的，可以使用 `formSdk.getFieldInfo(fieldId)` 来获取字段属性，放到 `config` 参数中，其中里面的 `readOnly` 和 `disabled` 决定了这个字段的只读属性，如果字段只读需要将这两个属性赋值为 true
**请注意**：通过 `formSdk.getFieldInfo(fieldId)` 获取的 `readOnly` 并不准确 ,请使用表单 sdk 来获取字段编辑属性

**value 参数** ：
参数格式参见文档
该参数表示字段的值，通过表单 SDK 获取的字段值需要进行转换，才能放入 value 参数中，转换示例：

```javascript
/**
 * 因为从明细中获取的字段值与表格中数据的字段值格式不一致，需要转为表格中的字段数据结构
 */
function getTargetFieldData(data) {
  // 如果存在 specialObj 数组，将 id 用逗号拼接作为 content（如果 content 尚未设置）
  if (data.specialObj && Array.isArray(data.specialObj) && data.specialObj.length > 0) {
    // 优先使用已存在的 content，否则使用 id 拼接
    if (!data.content) {
      data.content = data.specialObj.map(item => item.id).join(',');
    }
  } else if (!data.content) {
    // 如果没有 specialObj 且 content 尚未设置，使用 value
    data.content = data.value;
  }

  // 处理下拉框/浏览按钮类型的字段
  // 如果有 specialObj，转换为 dataOptions 格式
  if (data.specialObj && Array.isArray(data.specialObj)) {
    data.dataOptions = data.specialObj.map(item => ({
      optionId: item.id,
      content: item.name
    }));
  }

  // 不同字段类型有不同的数据格式，可以根据 fieldType 字段类型转换为对应字段类型的数据格式
  return data;
}
```

**onChange参数**：
当值改变时会调用 onChange(value) ，value 为变化后的值，与组件的 value 参数的值格式一样。
示例：

```javascript
 const handleChange = (newValue) => {
    // 获取当前字段数据
    const fieldData = rowData[field.fieldId] || {};

    // 如果有 dataOptions，转换为 specialObj 格式
    let specialObj = null;
    if (newValue.dataOptions && Array.isArray(newValue.dataOptions)) {
      specialObj = newValue.dataOptions.map(opt => ({
        id: opt.optionId,
        name: opt.content
      }));
    }

    // 数据更新到表单明细
    if (!rowData.isVirtual) {
      const fieldMark = `field${field.fieldId}_${rowData.rowId}`;
      const updateData = { value: newValue.content };
      // 如果有 specialObj，添加到更新数据中
      if (specialObj) {
        updateData.specialObj = specialObj;
      }
      formSdk.changeFieldValue(`${fieldMark}_${rowData.rowId}`, updateData);
    }
  };
```
